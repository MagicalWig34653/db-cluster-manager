# ADR 0022: Native restic host backups

Status: **Partial implementation; fakes plus lab run E11 (real restic, 4 backends, SSH external host)**, 2026-10-27. [X14](../KONZEPT.md#scope-extension) is the owner requirement. This decision extends [ADR 0021](0021-backup-targets-copies-and-metastore-backup.md) without changing database backup formats, cluster recovery or copy promotion rules.

## Decision and alternatives

| Question | Chosen mechanism | Alternative and reason |
| --- | --- | --- |
| Integration | Run the restic CLI behind `internal/restic.Runner`; parse each command's documented JSON output. Tests inject a fake runner and require no binary. | Embedding restic internals would couple the product to restic's internal Go APIs and dependency graph. A CLI adapter has a narrow process boundary and uses the documented command surface. |
| Managed host execution | A fenced, journaled command goes to the enrolled agent on that host. Local `-restic-allow-path` roots constrain source and restore paths. | Running restic in the manager would require remote filesystem mounts, broad host credentials and a larger blast radius. |
| External host execution | Model `external-host` with `agent` or `ssh-plan` transport. An enrolled external agent is the preferred future execution path. The current SSH adapter reuses [ADR 0018](0018-ssh-cluster-provisioning.md)'s pinned-host-key transport, stores key and known-host data sealed, and carries the password/backend credentials over SSH stdin to a remote temporary password file and restic child. Host identity, transport and repository fields are immutable on update so a queued operation cannot be redirected. External agent enrollment remains unavailable. | Treating an external machine as a Swarm node would invent cluster membership. Blind SSH commands would bypass ownership, host-key checks and fencing. |
| Secrets | The manager stores password and backend credentials as sealed replicated documents, separate from the public source record. The agent command holds only secret **names**. A password is read from the agent's secret mount and passed to the restic child via `RESTIC_PASSWORD_FILE`; S3/rest-server credentials are passed only in that child's environment. They never enter argv, returned API records, normal logs or exported operation definitions. The child starts with a restricted environment. | Password in argv or a manager-wide environment is exposed to process listings, logs or other children. A password value in a runner step would be journaled. |
| Backends | Local absolute repository path, SFTP repository, S3-compatible repository or HTTPS rest-server. SFTP key/host-key setup must be provided as reviewed agent-side files; inline URL passwords are refused. | Arbitrary restic backends would expand credential and command-injection surface before each transport has an explicit policy. |
| Retention and integrity | After a successful backup, run the configured `forget --prune` policy, then `check --read-data-subset` when configured. `check` checks a percentage of packs, not a full restore. | A delete-only retention run leaves unreferenced data; a check without read-data-subset misses pack-data corruption. Full read on every backup can be prohibitive. |
| Restore | Require restore permission and a separate digest-bound operation approval. The agent accepts only a target under its allow-list, claims a previously absent path atomically and invokes restic with `--overwrite never`. It never restores into a live path or promotes a backup copy. | An overwrite-in-place restore could destroy live data and bypass the existing approval model. |
| Lock handling | Report restic lock failures, including possible stale locks, through a classified error. Never run `unlock` automatically. | Automatic unlock can break a live writer when lock freshness is misread. |

## Contract and evidence

`internal/restic` wraps backup, snapshots, forget, check, restore and stats. `restic --json` is a per-command option. The [restic scripting documentation](https://restic.readthedocs.io/en/stable/075_scripting.html) describes backup/check/restore JSON lines, snapshots/stats JSON documents, forget's JSON array and version-dependent prune output, as well as exit codes 10/11/12 for missing repository, lock and wrong password. [restic's retention documentation](https://restic.readthedocs.io/en/stable/060_forget.html) describes `forget --prune`; [repository checking](https://restic.readthedocs.io/en/stable/045_working_with_repos.html) describes `--read-data-subset`. The adapter classifies errors without returning raw stderr, which can echo secrets. It treats missing or malformed success summaries as failure.

The manager stores host sources in `host-sources` and sealed credentials in `host-source-secrets`. Managed source runs use the existing runner lock, operation journal, agent fencing, authorization and audit. External SSH runs use the same journal and lock; the SSH adapter selects an exact stored source ID and refuses changes to the command's repository and source paths. It adds `--quiet` to remote backups to avoid filling ADR 0018's bounded SSH output with frequent status events; the JSON summary remains the success evidence. A leader-only scheduler reads UTC cron schedules and sends failure events through the existing notification dispatcher. API routes are in [OpenAPI](../../api/openapi.yaml); only the administrator preset may create/change sources or request/approve a restore, while a scoped operator may start a backup and a viewer may read visible source metadata. External sources have global scope.

## Current limits and next gate

Tests used fake runners, fake agents, a fake SSH command runner, in-memory Raft and HTTP response recorders. No real restic executable, repository, host, SSH connection or restore was exercised. The current product agent image does not package restic. The manager's sealed secret copy is **not yet delivered** to a managed agent secret mount. Existing deployed global agents do not gain new host path mounts, restic allow-list flags or secrets through source creation; operators cannot assume a managed source is executable merely because it is stored. The external SSH adapter has not been validated on a real host and currently inherits ADR 0018's 64 KiB remote output cap; larger restic output fails closed. Independent external-agent enrollment remains unavailable. No UI exists. A repository initialization workflow, SFTP key and pinned-host-key lifecycle, target path mount/deployment workflow, streaming output limits and a real disposable restic matrix are still required before claiming end-to-end support. W12 stays in progress; W05/R1 gates are unchanged.

## Lab evidence and amendments (E11, 2026-10-27)

[E11](../../tests/p0/results/e11-restic.md) ran the wrappers against real restic 0.19.1 and found issues that change the contract: (1) every command is preceded by a bounded `restic cat config` probe (default 2 minutes) because restic retries rejected S3 credentials for more than ten minutes; (2) a cancelled context is reported as interrupted with a stale-lock hint, still without any automatic `unlock`; (3) the SSH runner offers only the host key types pinned in `known_hosts`; (4) the remote restore guard is an explicit `if ... exit`; (5) remote restic receives `HOME` and the child environment keeps `RESTIC_CACHE_DIR`/`XDG_CACHE_HOME`. The agent image now carries a pinned restic; deployment of allow-list flags, mounts and secrets is opt-in through `swarm.AgentMTLS.Restic`. Alternative considered: a Debian-based agent image with `ssh` for SFTP; not done, SFTP repositories are documented as needing a different image.
