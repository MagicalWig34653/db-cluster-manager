# E13 release-candidate lab run: not executed (host resources)

Date: 2026-10-30. Planned scope: fresh-install walkthrough on lab VMs, real-browser UI end-to-end, backup/restore/PITR with a local and an S3 (MinIO) target. **No lab VM was created.** This file has no lab results. Nothing below is a passing check of the product.

## Why the run did not start

Measured on the host before any VM was created (`uptime`, `df`, `sysctl vm.swapusage`, `top -l 1`):

| Sample | Value |
| --- | --- |
| 1-min load average | 584, then 37, then 18 (5-min: 244, 134, 107) |
| Data volume free | 10 GiB, then 9.2 GiB, then 8 GiB (volume 99-100 % full) |
| Swap | 13.1 of 14.3 GiB used (about 91 %), unchanged over the session |
| Memory | 3.1 GiB unused at the first sample, 0.13 GiB unused at the last (compressor 17-19 GiB) |
| CPU | 5.7 % idle, later 43 % idle; sys time 61 % at the first sample |

Consumers were unrelated user work (a Virtualization.framework VM at 156 % CPU, iOS simulator poster apps, `fileproviderd`, Firefox, JetBrains IDEs, Xcode). The `colima:default` profile (6 CPUs / 8 GiB, foreign) was running; the two `thermoctl-*` Lima VMs were stopped. None of it was touched.

A lab session needs about 12 GiB RAM for three VMs, tens of GiB of thin disk growth (images built in the VMs, Galera data, backups) and a host disk guard (`E9_MIN_FREE_GIB`, default 4 in E12) that 8 GiB free cannot keep once images are built. With swap nearly exhausted, starting 12 GiB of VM RAM risks stalling the whole machine, and timings would reflect swapping rather than the product (see [e4-rerun-not-run.md](e4-rerun-not-run.md)). The run was therefore not started. Resume when: at least 40 GiB of host disk free, swap use well below the limit, and 1-min load below about 30 for the length of a run.

Cleanup proof: no `dbcm-lab-` VM, Docker context or Colima profile was created, changed or deleted; `bin/lab` was not built or run in this session.

Re-check at 18:01 after the coordinator reported a reset limit: load had dropped (12.8 / 7.6), but the data volume showed 0 GiB free (100 % full) and swap was still about 90 % used. `limactl list` showed no `dbcm-lab-` VM. The run was not started; a Galera lab on a full disk would fail on image builds and VM disk growth, not on the product.
